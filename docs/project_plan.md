# Java学習プロジェクト計画（AWS用語集＋フラッシュカードアプリ）

## 背景・目的

- 転職に伴い、入社前に案件面談が発生する予定。
- 弱み：Javaスキル・AWSスキルが浅い。AIを使った開発経験もない。
- この3点を同時に補強するため、Claude Codeを使ったJavaアプリ開発に取り組む。

## 制約条件

- 面談まで：**〜2週間程度**
- 開発時間：**1日1時間程度**（現職の引継ぎが忙しいため）
- AWS：**無料枠のみで完結させる**
- 開発環境：**Claude Code**

## 確定事項

- プロジェクト名：`flash-anki-app`
- パッケージ名：`io.github.rakisuto.flashankiapp`（GitHubユーザー名`rakisuto`の実ドメインに基づく逆ドメイン形式）
- 言語／フレームワーク：Java 21（LTS）+ Spring Boot 3.x
- ビルドツール：Gradle
- 初期依存関係：Spring Web、Spring Data JPA、H2 Database（ローカルDB。後にDynamoDBへ移行）

## 作るもの：AWS用語集＋学習進捗トラッカー（縮小版）

単なる用語CRUDではなく、以下を組み合わせてJava力・AWS力の両方を鍛える。

### 残す機能（芯）
- Spring Boot（Java）でAPI実装
- DynamoDBに実際にAWS SDK for Javaで接続し、用語データをCRUD
- IAMの最小権限ロール設計
- フラッシュカード形式の復習機能（正答率に応じて苦手な用語を優先出題）→ Javaロジックの練習になる

### 今回は削るもの（時間対効果が低いため）
- Lambda + API Gatewayへのデプロイ
- S3への画像アップロード
- EC2 / Elastic Beanstalk運用

→ ローカルで動作し、DynamoDBという実在のAWSリソースに接続できていれば、面談で語る材料としては十分。デプロイを見送った判断自体も「時間対効果を考えた判断力」として説明可能。

## スケジュール（2週間 × 1h/日、合計約12h）

| Day | 内容（1h） |
|---|---|
| 1 | AWSアカウント作成／請求アラート・Budgets設定／IAMユーザー作成（ルートは封印） |
| 2 | Spring Boot雛形作成（Claude Codeでプロジェクト生成）＋ CLAUDE.md作成 |
| 3 | 用語データのモデル設計（カテゴリ、正答率などのフィールド） |
| 4 | ローカルH2 DBでCRUD実装 |
| 5 | フラッシュカード出題ロジック（苦手優先アルゴリズム） |
| 6 | DynamoDBテーブル設計（パーティションキー等） |
| 7 | AWS SDK for Java導入、DynamoDB接続コード実装 |
| 8 | ローカルDB→DynamoDBへの切り替え・動作確認 |
| 9 | IAMロール/ポリシーを最小権限で書き直す |
| 10 | バグ修正・エラーハンドリング |
| 11 | 用語データを充実させる（CLF-C02範囲を入力しながら学習） |
| 12 | README／アーキテクチャ図作成 |
| 13 | 予備日（遅れの吸収） |
| 14 | 面談用トーク整理（何を作ったか・なぜその設計か・苦労した点） |

## AWSを無料で完結させるための注意点

- DynamoDBは永年無料枠（25GBストレージ＋一定のオンデマンドリクエスト）があるため、個人利用なら基本無料。
- Day1で必ず請求アラート（例：$1超で通知）とAWS Budgetsを設定。
- 使い終わったリソースはこまめに削除。
- Lambda/EC2を使わない構成なので、そもそも課金リスクは低い。

## ポートフォリオ公開時の注意点

- 認証情報（アクセスキー等）は`.env`／環境変数に逃し、`.gitignore`に含める。これ自体をREADMEで「セキュリティ意識」としてアピールできる。
- 見る側がAWSアカウントを持っていなくても評価できるよう、READMEに以下を含める：
  - アーキテクチャ図（Spring Boot → DynamoDB、IAMロール構成など）
  - スクリーンショット／簡単な動作GIF
  - 設計判断の理由
- 面談官は「動くデモ」より「設計判断を説明できるか」を重視することが多い。

## Java学習の進め方（コードを書かせて、レビューする型）

自分で手を動かして書くのではなく、Claude Codeに実装させ、レビュー・質問を通じて理解を深めるスタイルを採用。

### 1機能あたりの学習サイクル（1h想定）
1. **実装依頼**（〜20分）：Claude Codeに機能実装を依頼
2. **質問・レビュー**（〜25分、最重要フェーズ）：
   - 「このクラス設計にした理由は？」
   - 「なぜここでOptionalを使っているの？」
   - 「このtry-catchの範囲はなぜこの粒度？」
   - 「もし〇〇の場合、このコードはどう動く？」
3. **テストコードの模写**（〜15分）：Claude Codeにテストの見本を1つ書いてもらい、異常系など別ケースを自分で模写して動かす
4. **振り返り**：学んだことを`learning_log.md`に記録

### 面談で語れるポイント
「AIに書かせて終わり」ではなく、AIの出力に疑問を持ち、質問し、理解した上でテストで検証したプロセス自体が、AI時代のエンジニアとして評価されるアピールになる。

## Claude Codeの使い方メモ

- **CLAUDE.md**：プロジェクトルートに置く申し送り事項ファイル。技術スタック、規約、よく使うコマンドなどを書く。最初は空でよく、開発しながら追記していく。
- **Skill**：繰り返し使う手順・ノウハウをまとめたもの。今回は「DynamoDBテーブル設計の型」「IAMポリシー設計の型」などが固まってきたらスキル化を検討（最初の1〜2週間は不要）。
- **learning_log.md**：CLAUDE.mdとは別に、その日質問したこと・理解したことを記録する学習ログ。面談前の振り返りにも使う。

## 進捗管理について

進捗状況（何日目まで終わったか、何を実施したか）は、本ファイルではなく別ファイル `progress_log.md` にて管理する。本ファイルはあくまで「方針・計画」の定義用とし、進捗によって内容が変わるものではない（スケジュールや方針自体を見直す場合のみ更新する）。
